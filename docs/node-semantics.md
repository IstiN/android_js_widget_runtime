# Node semantics: Flutter versus Android

One table per registered node type (plan 6.1 A3, issue #4). Flutter behavior
comes from the pinned contract node pages
(`.conformance/js_widget_runtime/docs/contract/nodes`), the Android column
mirrors the mapper registry (`NodeMappers.kt`). Generated by
`scripts/gen-node-semantics.mjs`; regenerate after mapper changes.

Support status: `yes` = mapped to a real view; `partial` (host contract) =
a host surface fills the slot; `partial` (fallback) = reference fallback card.

## Minimum SDK

`minSdk = 17` (family target device: Tegra 2, Android 4.2.2 = API 17,
issue [#6](https://github.com/IstiN/android_js_widget_runtime/issues/6)).
Every >API 17 API in the tree is replaced or
`Build.VERSION.SDK_INT`-guarded; the card factory guards
`View.setElevation` behind `SDK_INT >= 21` — below 21 the card renders
without the shadow. Lint `NewApi` reports zero errors at `minSdk 17`.
